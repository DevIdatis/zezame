Zezame es una aplicación para fichar el tiempo de trabajo de un equipo: iniciar y pausar el cronómetro, asociar cada sesión a un proyecto y una actividad, y visualizarlo todo en un calendario y en reportes. En la línea de Sesame, pero con una interfaz propia y colorida.

Frontend Angular 20 Backend .NET 8 BBDD PostgreSQL Tiempo real SignalR Auth JWT
01

Qué es y para qué sirve

El corazón de Zezame es un cronómetro: un usuario ficha cuando empieza a trabajar, hace pausas cuando descansa y detiene la jornada al terminar. Cada entrada de tiempo se puede asociar a un proyecto y a una actividad concreta, de modo que después se sabe en qué se fue el tiempo.

Sobre esa base, la aplicación añade organización de equipo (proyectos con miembros y tareas), una vista de calendario con mapa de calor de horas por día, reportes de productividad con ranking de equipo, y ajustes de perfil y apariencia. Todo el estado del cronómetro se sincroniza en tiempo real entre pestañas y dispositivos mediante SignalR.

02

Cómo está construida

Tres piezas: una SPA de Angular que el usuario ve en el navegador, una API REST en .NET que aplica la lógica y la seguridad, y una base de datos PostgreSQL. La API sigue una arquitectura por capas (Dominio · Infraestructura · Api). Además del REST clásico, un canal SignalR empuja los cambios del cronómetro al instante.

04

Modelo de datos

Cinco entidades. Todas comparten Id, fechas de creación/actualización y borrado lógico (IsDeleted).

User usuario
Email, contraseña (hash), nombre, Role (User/Coordinator/Admin), zona horaria e idioma.
Project proyecto
Nombre, descripción, color, emoji, Status (Active/Paused/Completed), fecha límite y un dueño.
ProjectMember miembro
Une un User con un Project — así un proyecto tiene un equipo.
Activity actividad / tarea
Tarea dentro de un proyecto: nombre, emoji, Status, estimación y a quién está asignada.
TimeEntry entrada de tiempo
El fichaje: inicio, fin, duración, Type (Work o Break) y las referencias opcionales a proyecto y actividad.

06

Roles y seguridad

El acceso se autentica con JWT (token de 24 h). El registro público siempre crea un usuario básico; los roles elevados los concede un administrador. Las contraseñas se guardan con BCrypt y las claves sensibles viven en user-secrets, fuera del repositorio.

RolPuede
User Fichar su tiempo, ver sus proyectos, calendario y reportes propios.
Coordinator Además: crear y gestionar proyectos, crear actividades, añadir miembros y ver el ranking del equipo.
Admin Control total sobre cualquier proyecto y recurso.
07

Cómo ejecutarla en local

Base de datos (Docker)

Levanta PostgreSQL. La app espera la base zezame_db en el puerto 5432.

docker run --name db -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=masterkey -e POSTGRES_DB=zezame_db \
  -p 5432:5432 -d postgres:15

Backend (.NET)

Configura los secretos, aplica las migraciones y arranca la API en https://localhost:7107.

cd zezame-backend
# claves fuera del repo (una sola vez)
dotnet user-secrets set "Jwt:Key" "<clave-de-32+-caracteres>" --project Zezame.Api
dotnet user-secrets set "ConnectionStrings:Default" \
  "Host=localhost;Port=5432;Database=zezame_db;Username=postgres;Password=masterkey" --project Zezame.Api

dotnet ef database update -p Zezame.Infrastructure -s Zezame.Api
dotnet run --project Zezame.Api --launch-profile https

Frontend (Angular)

Instala dependencias y sirve la SPA en http://localhost:4200.

cd zezame-frontend
npm install
npm start
